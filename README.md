# Исполнители — Робот-садовник

Браузерная учебная среда по мотивам «Исполнителей» К. Ю. Полякова. Программа
управляет Роботом на клетчатом поле: нужно засадить грядки и прийти на базу.
Стены и засаженные клумбы непроходимы.

Пользовательская документация: [справочник команд](docs.html). Кнопка «Справка»
в редакторе открывает его в отдельной вкладке. Справочник включает примеры,
описание возможностей браузерной версии и благодарность К. Ю. Полякову
со ссылками на оригинальную среду и методические материалы.

## Запуск

Готовая версия работает целиком в браузере, включая разбор и исполнение программ.
Сервер, Node.js и подключение к Интернету пользователю не нужны: после сборки
откройте **`index.html`** в корне проекта или **`dist/index.html`**.

Для разработки нужны Node.js 22+ и npm:

```sh
npm ci
npm test
npm run build
npm run format:check
```

Сборка создаёт в папке `dist` страницы `index.html` и `docs.html`, стили
`styles.css` и `docs.css`, а также автономный `bundle.js`.
Корневой `index.html` подключает скрипт из `dist`; страница внутри `dist` подключает
скрипт из своей папки. Для распространения скопируйте всю папку `dist` и откройте
`index.html` внутри неё. Зависимости фиксируются в `package-lock.json`; CDN во время
работы нет.

При сборке содержимое страниц, стилей и скрипта определяет идентификатор версии.
В `dist` ссылки на скрипт и CSS содержат `?v=…`, а кнопка «Поделиться» добавляет
версию к адресу страницы. Поэтому новая опубликованная сборка и новые ссылки
не используют файлы, закэшированные от предыдущего выпуска. Имена локальных файлов
остаются прежними, открытие через `file://` поддерживается.

## Публикация на GitHub Pages

В настройках репозитория **Settings → Pages → Build and deployment → Source**
выберите **GitHub Actions**. Workflow `.github/workflows/pages.yml` при обновлении
`main` устанавливает зависимости, проверяет форматирование, собирает приложение,
запускает тесты и публикует содержимое `dist`. В pull request выполняются проверки
без публикации. Повторный деплой можно запустить через **Actions → Build and deploy
GitHub Pages → Run workflow** для ветки `main`.

Публикация исходников через **Deploy from a branch → main / (root)** не подходит:
`dist` создаётся при сборке и не хранится в Git. Без сборки запрос `dist/bundle.js`
возвращает `404`, и обработчики кнопок не запускаются.

## Архитектура

```text
исходный текст → Lexer → токены → Parser → CST → AstBuilder → AST
                                                        ↓
                                                     Analyzer
                                                        ↓
                                                     Runtime
                                                        ↓
                                 Interpreter → RobotHost / ProgramConsole
```

| Модуль | Ответственность |
|---|---|
| `language/tokens.js` | Определения токенов Chevrotain |
| `language/lexer.js` | Лексический анализ и позиции ошибок |
| `language/grammar.js` | Правила синтаксиса Chevrotain, без исполнения |
| `language/grammar.ebnf` | Читаемое формальное описание грамматики |
| `language/ast-builder.js` | Преобразование CST в независимое AST |
| `language/parser.js` | Публичный интерфейс парсера и синтаксические ошибки |
| `language/formatter.js` | Форматирование кода с сохранением токенов, строк и комментариев |
| `language/vocabulary.js`, `translate.js` | Русские и английские имена команд, переключение языка исходного текста |
| `language/analyzer.js` | Проверки имён, областей видимости, вызовов и типов |
| `language/compiler.js` | Последовательность стадий компиляции |
| `runtime/values.js`, `environment.js`, `operators.js` | Значения, массивы, области видимости и операции |
| `runtime/builtins.js` | Сигнатуры и реализации встроенных функций и датчиков |
| `runtime/runtime.js` | Исполнение AST; выдаёт шаги и запросы внешних действий |
| `runtime/robot-host.js` | Исполнение команд Робота с анимацией |
| `runtime/cancellation.js` | Прерываемые ожидания |
| `interpreter.js` | Управление запуском, шагами и остановкой |
| `robot.js`, `maze.js` | Модель Робота/поля, Canvas-отрисовка, чтение `.maz` |
| `sharing/task-link.js` | Чтение параметров URL и сохранение задачи в ссылке |
| `files/program-file.js` | Экспорт `.prg` в Windows-1251 или UTF-8 |
| `ui/task-share.js`, `ui/program-file.js` | Диалоги копирования ссылки и скачивания программы |
| `editor/history.js`, `ui/code-editor.js` | История текста и выделения, ввод, отмена и повтор изменений |
| `editor/snippets.js`, `ui/command-palette.js` | Каталог команд и вставка шаблонов в редактор |
| `ui/program-console.js`, `app.js` | Потоковый вывод, ввод и интерфейс |

Лексер, парсер, анализатор и Runtime не зависят от DOM. Выполнение AST не
использует `eval` или генерацию JavaScript из пользовательской программы.
Обычный и пошаговый режимы используют один генератор Runtime: процедуры и
вычисления выполняются одинаково. Остановка отменяет ввод, анимацию и ожидания;
устаревший асинхронный результат не может изменить новый сеанс.

## Язык

Спецификация: `robot.chm` из [официального архива](https://kpolyakov.spb.ru/download/robowin.zip).
[Методика обучения](https://kpolyakov.spb.ru/school/robots/methodic.htm).
Полная грамматика проекта: [language/grammar.ebnf](language/grammar.ebnf).

```text
целые старт = 2;

Основная()
{
    целые i;
    повтори (старт)
    {
        если (грядка) посади;
        если (впереди_свободно и не впереди_клумба)
            вперед(1);
    }
    выводстр "Факториал: ", Факториал(5);
}

целые Факториал(целые n)
{
    если (n <= 1) возврат 1;
    возврат n * Факториал(n - 1);
}
```

Реализованы:

- Именованная главная процедура с `()` или без них; глобальные и локальные
  переменные; процедуры и функции, параметры и рекурсия.
- Типы `int/целые`, `float/дробные`, `char/символы`, `logical/логические`.
- Присваивание `=` и `:=`, арифметика `+ - * / % ^`, сравнения
  `== != <> < <= > >=`, логика `! / не / not`, `& / и / and`, `| / или / or`.
- `повтори/repeat`, `пока/while`, `цикл/for`, `если/if`, `иначе/else`,
  `прервать/break`, `продолжить/continue`, `возврат/return`.
- Однооператорные тела без фигурных скобок; комментарии `//` и `/* … */`.
- Массивы и матрицы с нулевыми индексами; передача по значению.
- Строки в `char[]`, присваивание, объединение и функции `length/длина`,
  `copy/фрагмент`, `pos/позиция`, `insert/вставить`, `delete/удалить`.
- `ввод/input`, `cin >>`; `вывод/print/печать`, `выводстр/println`,
  `cout <<`, `coutln <<`, форматирование `значение:ширина:точность`,
  `очистить/clrscr`. Ввод происходит в консоли без блокирующего `prompt`.
- `pi`, `trunc`, `round`, `sign`, `random`, `sqrt`, `abs`, `sin`, `cos`, `tan`,
  `sing`, `cosg`, `tang`, `arcsin`, `arccos`, `arctan`, `arctan2`,
  `arcsing`, `arccosg`, `arctang`, `arctan2g`, `exp`, `ln`, `lg`.

Обратная косая черта в строке является обычным символом: `"\"` содержит один
символ, как в оригинальных примерах с путями Windows. Для кавычек одного вида
внутри строки используйте другой вид кавычек снаружи.

Сохранены расширения прежней версии проекта: `повтори N раз`, условия без
круглых скобок, необязательные `;`, прежние псевдонимы команд и датчиков.
Новые примеры рекомендуется писать в официальном синтаксисе со скобками и `;`.

## Команды Робота

| Команда | Действие |
|---|---|
| `вперед(n)`, `назад(n)` | Перемещение на неотрицательное целое число клеток; аргумент может быть выражением |
| `налево`, `направо`, `кругом` | Поворот на 90° влево, 90° вправо, 180° |
| `посади` | Посадка в незасаженную грядку |
| `впереди_стена`, `сзади_стена`, `слева_стена`, `справа_стена` | Проверка стены или границы поля |
| `впереди_клумба`, `сзади_клумба`, `слева_клумба`, `справа_клумба` | Проверка соседней засаженной клумбы |
| `впереди_свободно`, `сзади_свободно`, `слева_свободно`, `справа_свободно` | Проверка возможности движения |
| `грядка`, `база` | Проверка текущей клетки |

Вычислительные программы без обращений к Роботу завершаются без проверки базы.
Для управления: F5 — запуск/продолжение, F10 — шаг, Esc — остановка,
Ctrl+R — сброс. При изменении текста между шагами начинается новый сеанс.

Кнопка **«Форматировать»** над кодом или **Alt+Shift+F** расставляет отступы
в 4 пробела, переносы строк и пробелы между элементами программы. Открывающая
фигурная скобка ставится на отдельной строке у процедур, условий и циклов. Форматирование
сохраняет команды, строки, комментарии и точки с запятой. Если синтаксис нарушен,
исходный текст сохраняется, а ошибка выводится в консоль. Во время выполнения
программы форматирование недоступно.

Кнопки **↶ / ↷** и **Ctrl+Z / ⌘Z** отменяют изменения. Для повтора —
**Ctrl+Shift+Z / ⌘⇧Z** или **Ctrl+Y**. История хранит до 100 действий, включая
ввод, вставку, Tab, форматирование, очистку, выбор примера и переключение языка.
Непрерывный набор объединяется в одно действие; отмена возвращает также выделение
и положение прокрутки. Открытие другой задачи по ссылке начинает новую историю.
Изменение текста останавливает текущий запуск или пошаговый сеанс.

**«Команды»** открывает список с поиском по русскому и английскому названию:
команды Робота, датчики, операторы, типы, ввод/вывод и функции. Выбор заменяет
выделенный текст либо вставляет шаблон в позицию курсора. Первый параметр
выделяется для ввода, многострочный шаблон получает отступ текущей строки.

**«Язык команд: Русский / English»** переводит известные команды и ключевые слова
во всём редакторе и задаёт язык вставляемых шаблонов. Перевод использует токены
и синтаксическую структуру: имена пользовательских процедур и переменных,
комментарии, строковые литералы и форматирование сохраняются. Синтаксически
незавершённый текст не изменяется, диагностика показывается в консоли.
Общие обозначения вроде `sqrt`, `pi`, `cin` и `cout` сохраняются. Вызовы без
равнозначного варианта в другом языке также сохраняются: например, графический
`влево(90)` не заменяется на команду Робота `left` без аргументов.

Для полного перевода условий Робота добавлены английские названия датчиков:
`wall_ahead`, `flowerbed_ahead`, `free_ahead` и аналогичные с окончаниями
`_right`, `_behind`, `_left`; `garden`, `base`, `painted` соответствуют
`грядка`, `база`, `клетка_закрашена`. Это расширения браузерной версии; русские
имена остаются доступными. Английские имена датчиков теперь также зарезервированы.

## Ссылки на задачи

Кнопка **«Поделиться»** создаёт ссылку с текущим кодом, стенами, грядками, базой,
начальной позицией и направлением Робота. Скопируйте ссылку и отправьте другому
человеку или откройте и сохраните в закладках. При открытии восстановится задача;
программу запускает получатель. Уже посаженные во время выполнения цветы в ссылку
не входят. Последующие правки не изменяют ранее созданную ссылку.

Поддерживаются URL-параметры `maze` и `program` после `?`, например:

```text
https://hvost239.github.io/executor/?maze=B&program=main%7B%7D
```

`program` — исходный текст программы, `maze` — текст `.maz` или JSON-снимок,
созданный приложением. Можно передать один параметр или оба. Значения кодируются
через `URLSearchParams`, чтобы переносы строк, кириллица, `+`, `&` и `#` сохранились:

```js
const url = new URL('https://hvost239.github.io/executor/');
url.search = new URLSearchParams({
    maze: '2xb\n.w.\n...',
    program: 'Решение { вперед(1); посади; вперед(1); }',
}).toString();
```

Кнопка создаёт тот же набор параметров в части после `#`: длинный код и поле
остаются в браузере и не увеличивают URL HTTP-запроса к GitHub Pages. Параметры
из `#` имеют приоритет над одноимёнными параметрами из `?`. Формат JSON лабиринта
версии 1: `{ "v": 1, "rows": ["020", "010", "000"], "base": [2, 0], "start": [0, 0, 1] }`.
Каждая строка описывает ряд квадратного поля; `0` — пустая клетка, `1` — стена,
`2` — грядка, `3` — стена и грядка. `base` — координаты базы или `null`,
`start` — `[x, y, направление]`, координаты от нуля; направления: 0 вверх,
1 вправо, 2 вниз, 3 влево. Такой снимок сохраняет также базу на грядке и направление
Робота на базе, которые нельзя одновременно выразить одним символом `.maz`.

Ссылка самостоятельна и не требует базы данных. Для обмена используйте
опубликованный сайт: `file://`-ссылка содержит путь к файлу на вашем компьютере.

## Сохранение программы в файл

**«Сохранить код»** или **Ctrl+S / ⌘S** открывает окно с именем файла и кодировкой.
По умолчанию имя берётся из главной процедуры, расширение — `.prg`. Кнопка
«Скачать .prg» передаёт файл браузеру; место сохранения определяется его настройками.
Можно сохранить и незавершённую программу.

Оригинальная справка (`robot.chm`, «Работа с файлами») определяет `.prg` как
текстовый файл. Все 141 примера из [официального дистрибутива](https://kpolyakov.spb.ru/download/robowin.zip)
используют Windows-1251, CRLF и не содержат BOM. Экспорт по умолчанию воспроизводит
этот формат; проверка корпуса сравнивает экспорт с исходными файлами побайтово.
Для символов, которых нет в Windows-1251, можно выбрать UTF-8. Код редактора
при сохранении не изменяется; неподдерживаемые символы не заменяются на `?`.

## Границы совместимости

Сейчас подключён исполнитель Робот. Вызовы команд Черепахи, Чертёжника и
графических примитивов синтаксически разбираются; их выполнение требует
соответствующего исполнителя и выдаёт понятную ошибку в режиме Робота.
Эти исполнители и графический экран пока не реализованы. `RGB` доступна как
числовая функция. Полная совместимость пользовательского интерфейса оригинала
(например, отладка до курсора) не является частью грамматики.

Ограничения браузерной среды: до 10000 элементов массива, до 256 вложенных
вызовов и до 1 000 000 шагов программы. Два последних предела настраиваются
в параметрах Runtime/Interpreter. `повтори` и перемещение принимают
неотрицательное целое число; отрицательные значения не превращаются молча
в положительные. Числа хранятся в JavaScript Number, поэтому арифметика очень
больших целых может отличаться от оригинального Windows-приложения.

## Проверки совместимости

`npm test` запускает тесты лексера, грамматики, семантики, типов, рекурсии,
массивов, строк, ввода-вывода, датчиков, отмены и совпадения Run/Step.

Оригинальные материалы не включены в репозиторий. Для дополнительной проверки
распакуйте официальный архив и задайте путь:

```sh
EXECUTOR_REFERENCE_DIR=/path/to/robowin npm test
```

Эта проверка компилирует 141 программу из `program/{robot,kurs,drawer,turtle,fractals}`
и исполняет все 47 программ из `program/robot` с соответствующими лабиринтами.
Для примеров с вводом используется число `3`. Некоторые оригинальные примеры
заканчиваются вне базы или не имеют базы: это отдельно от успешного исполнения
языковых конструкций. Проверка разбора графических примеров не означает,
что графические исполнители реализованы.
